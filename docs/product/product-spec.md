# Product Spec

## 1. Контекст продукта

- Продукт: чат-бот для MAX, который принимает документы и ссылки и возвращает краткую, структурированную выжимку.
- Формат поставки: MVP, пригодный для демо, пилотов и white-label продажи.
- Главная ценность: пользователь отправляет файл или URL и получает полезный результат за десятки секунд, не читая весь материал вручную.
- Позиционирование: не просто "бот", а продаваемый B2B-модуль суммаризации документов для MAX.

## 2. Что делает MVP

### Поддерживаемые входы

- PDF
- DOCX
- TXT
- URL
- вставленный текст как дополнительный вспомогательный формат

### Базовые режимы ответа

- `TL;DR`
- краткая выжимка
- подробная выжимка
- ключевые тезисы
- `action items`
- follow-up режимы вроде "сделать короче" или "сделать подробнее"

### Что пользователь видит

1. `/start` и краткое объяснение, что умеет бот.
2. Быстрые кнопки вроде "Сжато", "Подробно", "Тезисы", "Action items".
3. Приём PDF, DOCX, TXT или ссылки.
4. Служебный промежуточный статус: файл принят, документ читается, summary собирается.
5. Итоговый ответ с дополнительными действиями по результату.

## 3. Почему продукт продаваемый

- Понятный wow-effect в одном коротком демо.
- Сильный B2B use case: сокращение времени на чтение документов.
- Легко white-label-ить под агентства, интеграторов и корпоративные команды.
- Можно упаковать как вертикальное решение под HR, legal, sales, finance, обучение.

## 4. Целевые сегменты

| Сегмент | Боль | Что получает |
| --- | --- | --- |
| HR и рекрутинг | поток резюме, вакансий, policy docs | summary, навыки, риски, action items |
| Legal / compliance | договоры, приложения, регламенты | быстрый первый просмотр и риски |
| Sales / agencies | КП, брифы, ТЗ | summary, цели, сроки, blockers |
| EdTech / обучение | статьи, методички, long reads | конспекты, FAQ, тезисы |
| Media / editors | отчёты, пресс-релизы | TL;DR и ключевые цитаты |

## 5. Scope MVP

### Входит

- приём PDF, DOCX, TXT и URL;
- асинхронная обработка через очередь;
- короткая и расширенная выжимка;
- тезисы и `action items`;
- кэш результата по hash файла или нормализованному URL;
- базовая история документов;
- статус обработки и базовая диагностируемость.

### Не входит

- тяжёлый enterprise OCR как основной режим;
- идеальная работа со сложными таблицами и сканами;
- мультидок-сравнение;
- полноценный billing;
- knowledge base, папки и коллаборация;
- полноценный web admin UI на первом шаге.

## 6. UX-принципы

- Ответ не должен выглядеть простынёй текста.
- Пользователь должен быстро увидеть служебный статус и понимать, что система работает.
- Формат summary должен быть предсказуемым.
- Для длинных документов допустим двухшаговый UX: быстрый TL;DR, затем более полный разбор.
- Follow-up действия не должны требовать повторного полного парсинга документа.

## 7. Форматы ответа

| Режим | Задача |
| --- | --- |
| `TL;DR` | быстрый первый ответ |
| Краткая выжимка | основной режим по умолчанию |
| Подробно | более длинный разбор по блокам |
| Ключевые тезисы | вытащить главное без лишнего текста |
| `Action items` | выделить задачи и следующие шаги |
| FAQ / Q&A | позже развить в режим вопросов по документу |

## 8. Базовый пользовательский путь

1. Пользователь открывает бота и запускает `/start`.
2. Бот показывает режимы и примеры.
3. Пользователь присылает документ или ссылку.
4. Бот создаёт задачу, сообщает статус и начинает асинхронную обработку.
5. После завершения бот отправляет summary.
6. Пользователь может запросить углубление по результату.

## 9. Ограничения и риски продукта

- Слабый OCR на плохих сканах может ухудшить качество summary.
- Длинные документы могут быть дорогими и медленными в обработке.
- Сложная вёрстка PDF может ломать структуру текста.
- Слишком общий summary убивает perceived value, поэтому важна чёткая форма ответа.

## 10. Упаковка для продажи

- Сделать 3 демо-кейса: договор, коммерческое предложение, резюме.
- Продавать как "модуль суммаризации документов для MAX", а не просто как бота.
- Подготовить hosted, white-label и isolated deployment варианты поставки.
- Для первых сделок подойдут пилоты с 1–2 клиентами и демонстрация реальных кейсов.

## 11. Этапы развития после skeleton

1. Интеграция с MAX: webhook/long polling, отправка файлов и сообщений.
2. Intake + storage: сохранение документов, метаданных и hash.
3. Extraction: PDF/DOCX/TXT/URL, нормализация текста.
4. Queue pipeline: BullMQ jobs, статусы, retries.
5. Summarization: chunking, map-reduce, шаблоны промптов, post-processing.
6. Observability и packaging под демо и продажу.

## 12. Критерий готовности продукта на уровне MVP

- бот принимает поддерживаемые форматы;
- пользователь быстро получает первый служебный ответ;
- summary приходит в нескольких режимах;
- временные ошибки можно повторять безопасно;
- есть понятная видимость статусов и ошибок;
- архитектура позволяет white-label поставку без привязки к одному мессенджеру.
